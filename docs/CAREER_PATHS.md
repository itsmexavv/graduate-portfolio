# Explore a track before committing to one

You do not need to know your future job title to start. Use these projects to compare the work itself. One project is an experiment, not a commitment to a career.

| If you enjoy… | Explore | Start here | Your first improvement |
| --- | --- | --- | --- |
| Building screens and making workflows easy to use | Frontend or full-stack development | SmartFind | Add keyboard-friendly category filtering and an edit-product form |
| Designing rules, data relationships and predictable responses | Backend development | AttendFlow | Add a documented lateness rule and tests for boundary times |
| Cleaning data, checking numbers and explaining trends | Data analysis | PesoLens | Add a month-to-month comparison with empty-month handling |
| Finding edge cases and reproducing failures | QA or test automation | Any project + tests | Add browser tests for invalid inputs and persistent data after reload |
| Solving graph problems and explaining correctness | Software engineering with an algorithm focus | AccessPath | Add an alternative routing strategy and compare results on fixtures |
| Understanding how programming tools work internally | General software engineering or language tooling | MiniLang | Add comparison expressions with lexer, parser and interpreter tests |

These projects do not cover every field. Cybersecurity, machine learning, mobile development and infrastructure need additional experiments if those subjects interest you.

## A four-week exploration plan

**Week 1 — Try the work.** Run every project. Spend 30–60 minutes reading each domain module and its tests. Explain one function in your own words. Record which activities make you curious.

**Week 2 — Make a contribution.** Pick two projects. Implement one small extension in each. Use a branch, keep focused commits, and add a meaningful test for the changed behavior.

**Week 3 — Go deeper.** Choose the more enjoyable project. Improve its error handling, documentation and usability. Write a design note about one tradeoff you encountered. Ask a classmate to try it and fix the issues they can reproduce.

**Week 4 — Practice showing your work.** Record a demo, update screenshots, describe your actual contribution and prepare a short walkthrough of the code and tests. Browse actual job descriptions you are considering and identify any repeated skills you still need to learn.
